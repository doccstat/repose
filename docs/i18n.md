# Language support

English is the source and current production fallback. Android follows the system
or app language selection; unsupported languages fall back to English.
`i18n.json` explicitly lists no additional target locales yet. UI strings live in
`res/values/strings.xml`; settings values, identifiers and secrets are not translated.
Native controls support RTL, dynamic colors and scalable text. Debug builds include
Android's expanded `en-XA` and RTL `ar-XB` pseudolocales.

Additional languages must be selected explicitly. Generate their Android catalogs
from the English source with an approved translation tool/LLM into disposable build
output (`dist/translations`), apply selective per-locale overrides, validate complete
keys/placeholders/plurals and review destructive-action/error wording before packaging.
Do not commit generated catalogs or translate credentials/user content. Production
locale filters and generated LocaleConfig must reflect only reviewed packaged locales.

Time pickers and summaries follow Android's 12/24-hour preference. Weekday chips
use localized names, full accessibility labels and the locale's first weekday.
Duration summaries and counters use locale-aware formatting. Stored times keep the
HH:mm protocol; day lists and IANA zone identifiers remain language-independent.
Changing presentation never rewrites stored settings or credentials. Technical
diagnostic event codes, command protocols and the developer Python CLI use stable
English identifiers.
